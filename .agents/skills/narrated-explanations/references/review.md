# Review the explanation

For each beat, record the visible change, caption, spoken anchors and measured duration. Inspect these pairs rather than reviewing the script and visuals separately:

- Does a meaningful change appear promptly, before the narrator needs it?
- Does the narration identify the highlighted object and explain its implication?
- Are new substantive claims addressed? Are axes, old findings and source context visibly secondary?
- Is the confidence warranted by the supplied evidence?
- Can the review finish without opening anything or making a choice?

For playback, check a representative real clip and every transition: gesture gate, pause/resume position, buffering, manual navigation, automatic advance, final stop and replay. Seek to intermediate and terminal positions in animations. Verify total progress and caption changes. Opening optional evidence should pause narration; post-review exploration should not restart it.

For visuals, inspect every click state, including unhighlighted evidence and the final verdict. Check text fit, clipping, contrast, diagram identity and absolute timestamps. Inspect mobile playback controls separately from evidence legibility; a scaled desktop slide is not a mobile redesign.

For reusable code, test an unrelated data set with different node counts, time ranges and capacities. Confirm that the package imports no example manifest, story names, credential or provider-specific SDK. Validate the documented install and build commands from the repository lockfile.

For timing and cost, distinguish estimated, raw synthesized and final paced durations. Do not claim listening quality from a transcript or two-run stability from a single generation. A static-state MP4 is not a capture of the live animation.
